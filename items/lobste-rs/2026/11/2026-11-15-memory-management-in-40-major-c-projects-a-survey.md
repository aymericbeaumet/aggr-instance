C is well known for requiring manual memory management with malloc and free. And while many major projects do actually manage memory like this, many projects also implement higher-level memory management primitives such as regions (where objects allocated within a region need not be manually freed, freeing a region frees all objects allocated within the region at once), reference counting (manually incrementing and decrementing outstanding references, freeing an object only when its references go to zero), scope-based cleanup using compiler extensions, and a number of major C projects even actually implement garbage collection (fully automatic memory management).

Programmers sometimes assume that projects famous for diligence lean away from purely manual memory management. But [SQLite](https://theconsensus.dev/project/sqlite.html), famous for correctness, allocates 100% manually while [cURL](https://theconsensus.dev/project/curl.html) and [Redis](https://theconsensus.dev/project/redis.html) allocate mostly manually (94% and 79%), reference counting only some of their objects. Another surprising finding is that [Linux](https://theconsensus.dev/project/linux.html) and [QEMU](https://theconsensus.dev/project/qemu.html) in the last few years have been starting to use scope cleanup rules (i.e. compiler extensions) to automatically clean up memory, such as Linux's [`__free(kfree)`](https://github.com/torvalds/linux/blob/v7.2/drivers/input/touchscreen/raydium_i2c_ts.c?utm_source=theconsensus.dev&utm_medium=referral#L174) and QEMU's [`g_autofree`](https://github.com/qemu/qemu/blob/v11.1.2/block.c?utm_source=theconsensus.dev&utm_medium=referral#L855).

The Consensus tracks and indexes code for over 400 major software infrastructure [projects](https://theconsensus.dev/projects.html). This article surveys 40 of the C projects within this group, excluding test code, third-party code, and examples.

## Majority allocation strategy

To discover majority allocation we count allocation call sites (which is certainly a limited metric, not accounting for sub-region or size of allocation, etc.). [seL4](https://theconsensus.dev/project/sel4.html) is an exception to much of this article since it has no heap at all.

8 projects solely allocate with malloc, implementing no other general higher-level strategy for allocating. These projects are: [brotli](https://theconsensus.dev/project/brotli.html), [FreeRTOS](https://theconsensus.dev/project/freertos.html), [HAProxy](https://theconsensus.dev/project/haproxy.html), [libdeflate](https://theconsensus.dev/project/libdeflate.html), [lz4](https://theconsensus.dev/project/lz4.html), [SQLite](https://theconsensus.dev/project/sqlite.html), [xz-utils](https://theconsensus.dev/project/xz-utils.html), and [zlib](https://theconsensus.dev/project/zlib.html).
