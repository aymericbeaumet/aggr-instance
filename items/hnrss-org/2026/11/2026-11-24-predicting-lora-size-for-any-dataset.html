Given an SFT dataset, we can predict exactly the LoRA size required to fit it.

TLDR:

  • We develop a predictive theory of the capacity of a LoRA adapter as a function of its rank.
  • Unlike full-parameter fine-tuning, LoRA learns a decreasing amount per-parameter.
  • Given an SFT dataset, we can predict the LoRA size required to fit it.

At Engram, we train lots of models. We train models for individual users and update them when information changes. A major focus of our research is how to customize and adapt models efficiently at scale.

This post focuses on LoRA1. LoRA has become the predominant approach for customizing models in industry. While there exists a large body of knowledge on how to set the hyperparameters and train LoRA effectively2, 3, it’s still unclear how to set LoRA’s rank. Although it’s agreed-upon that LoRA underperforms full-finetuning on larger datasets, it’s not clear when this is the case. How big does a dataset have to be to require a larger LoRA?

In practice, smaller LoRAs enjoy a number of systems advantages, being lighter to load4, 5, faster to generate text from6, and easier to store on disk. For larger models, rank-1 can store quite a lot; some datasets, like RL data, can be represented in a small number of bits and often fit within a rank-one LoRA adapter (or smaller!7, 8, 9).

In this post, we develop a predictive theory and practical approach for sizing LoRA adapters to a new dataset. The idea is simple: the size of the LoRA required depends on how many bits it takes to encode the dataset under the base model. We use this idea to derive an exact formula for how many bits a single LoRA adapter can learn as a function of its rank.

We then extend our idea to measure the capacity of LoRA on full transformers. Since theory can’t predict the nonlinear behavior of deep transformers, we turn to an empirical solution: we generate synthetic datasets of exactly NN bits under the base model and train on them to measure LoRA’s capacity. Our capacity predictions hold up on real datasets: across a variety of settings, we can accurately determine the necessary rank of the adapter.

Information theory and LLMs

We begin this post with a basic primer on the connection between information theory and language modeling. Remember that our goal is to find the smallest adapter that fits a given dataset. To do that, we need to measure adapters and datasets in the same unit: bits.

Language modeling and Shannon

Language models assign probabilities to strings:

pθ(x)=∏ipθ(xi∣x<i)p_\theta(x) = \prod_i p_\theta(x_i \mid x_{<i})

A language model is, at its core, a text compressor10: a model that assigns high probability to data can encode it efficiently. And we’ve known this since the 1950s! By Shannon’s source coding theorem11, a model’s quality (its perplexity, or cross-entropy) corresponds directly to its effectiveness as a compressor. The number of bits needed to encode a string xx under a model θ\theta is its negative log-likelihood:

bitsθ(x)=−∑ilog⁡2pθ(xi∣x<i)\text{bits}_\theta(x) = -\sum_i \log_2 p_\theta(x_i \mid x_{<i})

Generating exactly N bits using an LLM

To measure the capacity of LLMs being trained with adapters, we need to generate data with a controllable number of bits. Prior work in this space creates data of fixed size with random generative processes, like randomly generated tables of facts13 or random strings of tokens.

To generate truly random data from an LLM, we leverage a tool called arithmetic coding. Arithmetic coding gives us the ability to transform probability distributions into codes; it represents the entire code using a single floating point number in [0,1)[0, 1) that we can turn into a sequence using pθp_\theta.

We take this one step further. A pretrained open-source model like Qwen or Inkling already provides likelihoods for text, so we can run arithmetic coding in reverse: start from NN random bits and decode them into text. The result is a sample from pθp_\theta whose code length under the model is NN bits. One can think of this as an implementation of Neural Linguistic Steganography14 using randomly selected codes.

Here’s an example of arithmetic coding in use. The following panel allows you to generate strings with exact bit counts under SmolLM2:

Code lengths come out slightly longer than the number of encoded bits because tokens are indivisible. In this example, queen is worth eleven bits (surprising!), while little carries just two bits. Later in this post we will generate many strings like this to build a dataset of exactly known size, then train an adapter on it to measure how many bits it can learn.

How much can LoRA store?

Given a matrix WW to adapt, LoRA works by training two matrices whose product is a low-rank update to WW:

W′=W+αrBA,B∈Rm×r,  A∈Rr×nW' = W + \frac{\alpha}{r} BA, \quad B \in \mathbb{R}^{m \times r}, \; A \in \mathbb{R}^{r \times n}

Here WW is an m×nm \times n matrix being adapted and AA and BB are the matrices trained via LoRA. Since rr is often much smaller than mm and nn, the total number of parameters trained by the LoRA is typically much smaller than training all of WW.

The parameter α\alpha is a rank-independent scaling factor; in this work, we fix α=256\alpha=256 to avoid conflating rank with learning rate.

Sizing LoRA, in theory

Prior work has estimated that the capacity of full transformer training scales roughly linearly with parameter count15, 16, 17. We don’t intuitively expect this to be true with LoRA, since some dimensions influence the model outputs more than others. Instead, we expect diminishing returns to capacity as rank increases. This is exactly what we see in practice, and it turns out we can predict the capacity curve quite cleanly using a simple statistical model.

Suppose we sample data from a model and then adapt one of its weight matrices to memorize that data. How much can we expect to increase the log-likelihood (and hence decrease the code length) with a rank-rr adapter? To second-order, log⁡pθ(x)\log p_\theta(x) looks like an inverted bowl in parameter space. How high we can climb on that bowl can be determined from the gradient and Hessian at the point θ\theta, and these are both random functions of the training data xx. Since the data is sampled from pθp_\theta, the statistics of the gradient and Hessian are determined by the Fisher information matrix, which greatly simplifies the calculations.

After some algebra, we find that the capacity of a rank-rr adapter is approximately,

C(r)≈12ln⁡2 E[∑i=1rσi(Z)2] bits,Z∈Rm×n, Zij∼iidN(0,1)C(r) \approx \frac{1}{2\ln 2}\,\mathbb{E}\left[\sum_{i=1}^{r}\sigma_i(Z)^2\right]\ \text{bits}, \qquad Z\in\mathbb{R}^{m\times n},\ Z_{ij}\stackrel{\mathrm{iid}}{\sim}\mathcal{N}(0,1)

where σi(Z)\sigma_i(Z) is the ii-th singular value of the random matrix ZZ. The capacity grows roughly linearly at low rank,

C(r)≈(m+n)22ln⁡2⋅rfor r≪min⁡(m,n),C(r) \approx \frac{(\sqrt m+\sqrt n)^2}{2\ln 2} \cdot r \qquad \text{for } r \ll \min(m,n),

but it plateaus as the rank increases and the singular values decrease. At full rank, the capacity is mn2ln⁡2\tfrac{mn}{2\ln 2} bits, recovering a classical result from Wilks’ theorem in statistics18.

For an 800M parameter Qwen3.5 model, which has 512×1024512 \times 1024 linear layers in its attention value projections (v_proj), the theory predicts about 378k bits, or 0.48 bits-per-parameter at full rank and 1.3-1.4 bits-per-parameter at low rank.

When we measure capacity using actual training, this prediction turns out to be quite accurate; C(r)C(r), the blue curve, is accurate at every rank:

Sizing LoRA, in practice

Theory predicts around 0.5-1.4 bpp when perturbing individual weight matrices. What about full transformers? When we adapt several matrices jointly, the capacity is more than the sum of its parts. We see super-additive scaling of capacity thanks to complementary interactions from adapting multiple weights at once19.

While the theory above cannot explain these super-additive effects yet, we do have a way to generate a dataset of a fixed size (measured above) and a way to measure how much a model learns from data (by checking its loss).

Extrapolating to the infinite-training regime. We fit a function to estimate the asymptote of the loss curve under infinite training, similar to20. This modeling allows us to train for a fixed number of steps and predict the asymptote of the loss under high compute, rather than perform the full training. It also allows us to avoid constantly sweeping learning rates, since different learning rates converge to the same capacity under infinite training.

We find a simple log-logistic curve fits our training runs well:

bits(T)=bits∞⋅TcTc+τc\text{bits}(T) = \text{bits}_\infty \cdot \frac{T^c}{T^c + \tau^c}

Here TT is the number of training steps, τ\tau is the step where the adapter has stored half its eventual bits, and cc sets how sharp the rise is; we fit this on runs of 1k steps and up, and report bits∞\text{bits}_\infty as the adapter’s capacity.

Naively, one might expect the total capacity to be the sum of each adapter’s capacity, and hence the bits stored per parameter to remain roughly constant as we adapt more and more layers. However, as we increase the number of layers, total capacity actually rises from 1.5 bits-per-parameter to 3.3:

Although the majority of our results assume capacity in the infinite-training regime, we can quickly model how even in the case of LoRA, capacity rises with the number of training steps21. A model that learns 10 KB of new information might forget 12 KB of old information. This setting provides a clean testbed for future research to investigate the connection between learning & forgetting.

Sizing LoRA capacity with real datasets

Remember that our goal is to estimate the rank of LoRA required to fit some arbitrary SFT dataset. To do this, we need a method for measuring the size of datasets. In the previous section, we used log-likelihood under θ\theta as a way to generate synthetic data of a precise size. Following the same logic, we can measure the log-likelihood of real data to compute its size under θ\theta.

Measuring the size of full datasets

We first extend the model’s context window to 2M tokens via YaRN22. If the data still doesn’t fit into context, we estimate its size in bits under the model by cutting it into windows of 2M tokens and summing the log likelihood:

bitsθ(D)≈∑k=1Kbitsθ(x(k))=−∑k=1K∑ilog⁡2pθ(xi(k)∣x<i(k))\text{bits}_\theta(D) \approx \sum_{k=1}^{K} \text{bits}_\theta\big(x^{(k)}\big) = -\sum_{k=1}^{K} \sum_{i} \log_2 p_\theta\big(x^{(k)}_i \mid x^{(k)}_{<i}\big)

where x(1),…,x(K)x^{(1)}, \dots, x^{(K)} are consecutive 2M-token windows of the dataset DD.

Although this gives us a slight overestimate for the total information content of a dataset, in practice we find the error to be small and the estimates useful enough to predict rank within 5% error.

Testing on real workspaces

We now test our ability to properly allocate adapters and train. We test on datasets of varying sizes scattered across the public internet as well as our and our partners’ workspaces.

For each new dataset, we first measure its size in bits under the model and read the predicted rank rr off the synthetic capacity curve. We then train LoRAs on the real dataset itself at ranks from r/2r/2 to 2r2r, and report the measured rank as the smallest rank that stores 95% of the dataset.

Even though our capacity estimates assume the training data is drawn from the base model, our predictions are extremely accurate on real datasets: the orange dots, the smallest LoRAs required to fit each dataset in practice, fall almost on the blue line, our estimate of a given LoRA rank's capacity.

Conclusion

This post described our work to automatically provision adapters of a fixed size by using information theory to estimate adapter capacity and relate it to the size of a given dataset. This gives a way to mint PEFT modules on-the-fly of the minimum size required for a given task.

In practice, we don’t always use LoRA. We’re exploring other options for parameter-efficient learning such as trainable prefixes23, sparse memory layers24, steering vectors25, GDN state, and trainable experts26. We find the landscape of PeFT methods contains a number of tradeoffs, and different modules work better for different tasks. We’re also working on other parts of this stack, such as more accurately estimating loss without training and understanding capacity in the finite-compute regime.

On a broader scale, examining how model capacity interacts with data size provides us a clean playground to investigate fundamental questions around how models learn.

Appendix

A: Theory

Intuitively, the capacity of the adapter is the number of bits it can store about the data it is trained on. We formalize this concept as the decrease in code length of training data, on average over the training distribution. When the training distribution differs from the base model, the decrease in code length comes from a combination of learning the signal — the change in distribution — and noise — the particulars of the individual training samples. We can simplify our study of capacity by sampling from the base model, eliminating the signal so that any reduction in code length comes from memorizing the noise in the training samples. While this is unrealistic, it gives conservative worst-case estimates of capacity per parameter, and as we will empirically demonstrate, the theory is predictive in more realistic settings as well.

Let pθ+δp_{\theta+\delta} denote the adapted model after a perturbation δ\delta to the model parameters. Here, the perturbation is trained to maximize the log-likelihood of the training data. To second order, the objective is approximately,

log⁡pθ+δ(x)≈log⁡pθ(x)+δ⊤g+12δ⊤Hδ\log p_{\theta+\delta}(x) \approx \log p_\theta(x) + \delta^\top g + \frac{1}{2} \delta^\top H \delta

where g=∇θlog⁡pθ(x)g = \nabla_\theta \log p_\theta(x) is the gradient (i.e., the score function) and H=∇2log⁡pθ(x)H = \nabla^2 \log p_\theta(x) is the Hessian. With enough samples x∼pθx \sim p_\theta, the Hessian HH is well-approximated by the negative Fisher, H≈−FH \approx -F.

Here, δ∈Rmn\delta \in \mathbb{R}^{mn} is a vector obtained by raveling a matrix-valued adapter Δ∈Rm×n\Delta \in \mathbb{R}^{m \times n}. If we optimize to find the best rank-rr adapter, the approximate increase in log-likelihood is,

max⁡rank⁡Δ≤r [  δ⊤g−12δ⊤Fδ⏟Q(δ)  ]\max_{\operatorname{rank}\Delta \le r}\ \Big[\; \underbrace{\delta^\top g - \tfrac{1}{2}\delta^\top F\delta}_{Q(\delta)}\; \Big]

To obtain a closed-form expression for the approximate increase in log-likelihood, we need one further assumption. As written above, the Fisher information is a matrix F∈Rmn×mnF \in \mathbb{R}^{mn \times mn}. If the Fisher information matrix admits a Kronecker-factorization27, F=F1⊗F2F = F_1 \otimes F_2, where F1∈Rm×mF_1 \in \mathbb{R}^{m \times m} and F2∈Rn×nF_2 \in \mathbb{R}^{n \times n} are invertible matrices, then in terms of the matrix-valued perturbation:

Q(Δ)≈⟨Δ,G⟩−12⟨F1Δ,ΔF2⟩Q(\Delta) \approx \langle \Delta, G \rangle - \frac{1}{2} \langle F_1 \Delta, \Delta F_2 \rangle

where G∈Rm×nG \in \mathbb{R}^{m\times n} is the gradient gg reshaped into a matrix. Now reparameterize in terms of Δ~=F11/2ΔF21/2\widetilde{\Delta} = F_1^{1/2} \Delta F_2^{1/2}. Then,

Q(Δ~)=⟨Δ~,Z⟩−12⟨Δ~,Δ~⟩=−12∥Z−Δ~∥F2+cQ(\widetilde{\Delta}) = \langle \widetilde{\Delta}, Z \rangle -\frac{1}{2} \langle \widetilde{\Delta}, \widetilde{\Delta} \rangle = -\frac{1}{2} \|Z - \widetilde{\Delta}\|_F^2 + c

where Z=F1−1/2GF2−1/2Z = F_1^{-1/2} G F_2^{-1/2} and c=12∥Z∥F2c = \tfrac{1}{2}\|Z\|_F^2 is constant in Δ~\widetilde \Delta.

Maximizing subject to the rank-rr constraint amounts to setting Δ~⋆\widetilde{\Delta}^\star to the truncated SVD of ZZ with the top rr singular values. With this optimal choice, the approximate increase in log-likelihood is,

Q(Δ~⋆)=12∑i=1rσi(Z)2Q(\widetilde{\Delta}^\star) = \frac{1}{2} \sum_{i=1}^r \sigma_i(Z)^2

The capacity of a rank-rr adapter is the expected increase, measured in bits. Recall that the entries of GG are gradients of the log-likelihood — that is, the score functions. Thus, in expectation, GG is mean zero and has covariance equal to the Fisher information matrix. When we multiplied GG by the inverse square roots to obtain the matrix ZZ, we effectively whitened the covariance so that ZZ has mean-zero, uncorrelated, unit-variance entries, and by a martingale CLT argument, they are approximately i.i.d. Gaussian. Thus, the capacity is approximately,

C(r)≈12ln⁡2E[∑i=1rσi(Z)2];Z∈Rm×n,  Zij∼N(0,1).C(r) \approx \frac{1}{2 \ln 2} \mathbb{E} \left[ \sum_{i=1}^r \sigma_i(Z)^2 \right]; \quad Z \in \mathbb{R}^{m\times n}, \; Z_{ij} \sim \mathcal{N}(0,1).

The singular values of ZZ follow a predictable distribution from random matrix theory. In the limit m,n→∞m, n \to \infty with m/n→γ∈(0,1]m/n \to \gamma \in (0, 1], assuming w.l.o.g. that m≤nm \leq n, the distribution of the mm rescaled squared singular values λ=σ2/n\lambda = \sigma^2/n (equivalently, the eigenvalues of ZZ⊤/nZZ^\top/n) converges to the Marchenko–Pastur law29 with density

ργ(λ)=(λ+−λ)(λ−λ−)2πγλ,λ±=(1±γ)2.\rho_\gamma(\lambda) = \frac{\sqrt{(\lambda_+ - \lambda)(\lambda - \lambda_-)}}{2\pi\gamma \lambda}, \qquad \lambda_\pm = (1 \pm \sqrt\gamma)^2.

with support λ∈[λ−,λ+]\lambda \in [\lambda_-, \lambda_+]. Let trt_r be the upper r/mr/m quantile of ργ\rho_\gamma, i.e., a fraction r/mr/m of the rescaled squared singular values lie above it. The first equation below is this definition. Summing the captured values, each worth σ2=nλ\sigma^2 = n\lambda, gives the second:

r=m∫trλ+ργ(λ) dλ,C(r)≈mn2ln⁡2∫trλ+λ ργ(λ) dλr = m\int_{t_r}^{\lambda_+} \rho_\gamma(\lambda) \, d\lambda, \qquad C(r) \approx \frac{mn}{2\ln 2}\int_{t_r}^{\lambda_+} \lambda\, \rho_\gamma(\lambda)\, d\lambda

The approximation becomes exact as the matrix grows with r/mr/m fixed. At 512×1024 it is within 0.4% of the exact C(r)C(r).

The integrals are still a bit unwieldy, but substituting λ=1+γ+2γcos⁡φ\lambda = 1 + \gamma + 2\sqrt\gamma\cos\varphi leads to a closed-form expression for the curve φ↦(r(φ),C(r(φ)))\varphi \mapsto (r(\varphi), C(r(\varphi))), with φ∈[0,π]\varphi \in [0, \pi]:

r(φ)=m⋅(1+γ)φ−2γsin⁡φ−2(1−γ)arctan⁡ ⁣(1−γ1+γtan⁡φ2)2πγ,C(r(φ))=mn2ln⁡2⋅φ−sin⁡φcos⁡φπ\begin{align*} r(\varphi) &= m \cdot \frac{(1+\gamma)\varphi - 2\sqrt\gamma \sin\varphi - 2(1-\gamma)\arctan\!\left(\frac{1-\sqrt\gamma}{1+\sqrt\gamma}\tan\frac\varphi2\right)}{2\pi\gamma}, \\ C(r(\varphi)) &= \frac{mn}{2\ln 2}\cdot\frac{\varphi - \sin\varphi\cos\varphi}{\pi} \end{align*}

To get C(r)C(r) at a given rank rr, solve the first equation for φ\varphi numerically (it is monotone in φ\varphi) and substitute into the second.

Low-rank limit. For r≪mr \ll m, the tail above trt_r shrinks to the edge λ+\lambda_+, so each direction captures about nλ+=(m+n)2n\lambda_+ = (\sqrt m + \sqrt n)^2, and

C(r)≈r(m+n)22ln⁡2C(r) \approx \frac{r(\sqrt m+\sqrt n)^2}{2\ln 2}

Normalizing by the number of LoRA parameters gives

C(r)r(m+n)≈1ln⁡2(12+mnm+n) bits per LoRA parameter\frac{C(r)}{r(m+n)} \approx \frac{1}{\ln 2}\left(\frac12+\frac{\sqrt{mn}}{m+n}\right)\ \text{bits per LoRA parameter}

For Qwen3.5-0.8B this gives 1.40 bits per LoRA parameter for v_proj (512×1024) and 1.32 for up_proj (1024×3584 with the smaller dimension first).

B: Experimental setup

Optimization. All training used the AdamW optimizer with a short linear warmup, cosine decay to zero, gradient-norm clipping, and no weight decay. All experiments are conducted on Qwen3.5-0.8B, although we expect our findings to transfer cleanly to other base models.

We use a combination of internal and external datasets:
