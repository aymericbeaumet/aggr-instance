1. There's some stuff simply not well optimized internally. Working on these now e.g. there's unnecessary internal hierarchy on all nodes that only needs to exist on a small subset (related to border boxes, overflow etc.)

2. Eager shader compilation. There's some glass and blur shaders that are compiled on load. These really shouldn't be.

4. THE BIG ONE. This demo is a bit of a monolithic beast. It doesn't just include Godot's implementation of React. You can reveal the code for any page in the demo, and edit the code live with an inline text editor. Genuinely bundled in this demo is a full TypeScript 7 implementation (based on Bun's Rust implementation) that type checks and compiles code to JS on the fly, and hot swaps components on the page live.

For the most part, this isn't designed as a performance demonstration, although there is a small section on repaints/relayouts. It's mostly just a demonstration of what's possible with the library.

Realistically, there's also the fact this is React. Its architecture is based on React Fabric (like React Native), so runtime performance should be pretty decent. I'm working on Hale, an abstract distributed systems language.

It's a traditional systems language in the sense that you have fine control over how resources are used, but it's abstract in the sense that you have to come to an agreement with the compiler about your intent around the resources, rather than directly declaring the machinery.

It's a distributed language in the sense that there is a higher level structural abstraction in the language that situates computations of the program within a recursive graph structure. Part of that structure incorporates message broker semantics. This gives the compiler a unified view of programs across arbitrary process boundaries. The structural abstractions also enable an effects+formal verification syntax within the language, which allows programmers to codify architectural decisions that are then checked by the compiler.

The compiler itself is infrastructure aware, and the highest layer of functionality it handles is configuring the environment into which applications deploy. The single language handles everything from individual memory allocations to distributed fleet deployments.

The language is close to v1, and I'm currently building a fully distributed inference-as-a-service application with it. Arbitrary hardware/supply matched against arbitrary callers/demand in real time.

I just got Beacon approved for the Apple App Store, it’s a mobile app for answering “which friend is free to talk right now?”

It’s a one-to-many phone call that only one person can answer. Send a beacon to a group, and everyone gets pinged at the same time. The first person who answers gets connected for a 1-1 call, and for everyone else the signal drops silently. It does not log any missed calls so there’s neither pressure to answer nor pressure to return calls.

Overall it works really well! It works best if you're able to join with at 4+ friends/family you’d like to chat with more. I have dozens of connections in the app now and it feels like magic to me. I press the button and get a random friend!
