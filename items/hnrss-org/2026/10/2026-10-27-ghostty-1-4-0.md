Ghostty 1.4.0 is a major release that includes large performance and memory improvements, a 100% complete Kitty graphics implementation including animation and relative placements (the first non-Kitty terminal to do so), SSH integration improvements, and hundreds more improvements and fixes across all platforms.

This release features **7 months of work** with changes from **172 contributors** over **2,889 commits**. Thank you to all the contributors, maintainers, community moderators, translators, packagers, and users who each helped make this release possible.

These release notes are painstakingly and lovingly hand-crafted by human Ghostty maintainers, including the full changelog. They take a combined 16+ hours to write, so please enjoy. 🥰

- [GHSA-4hwh-wx3w-3fqg](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-4hwh-wx3w-3fqg). Paste protection didn't treat carriage returns as line endings, so a paste could run a command without confirmation in programs that don't use bracketed paste. This requires user interaction (copy-paste) to trigger.
- [GHSA-mhff-mv4q-fp63](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-mhff-mv4q-fp63). Malicious Kitty graphics commands could crash or hang Ghostty, force huge allocations, or in limited cases read or delete files outside the allowed temporary directories. This only requires displaying malicious output.
- [GHSA-hcr9-7hcr-mjm8](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-hcr9-7hcr-mjm8). Malicious terminal output could crash Ghostty, closing every window, via tmux control mode. tmux doesn't need to be installed. This affects Ghostty 1.3.0 and 1.3.1.
- [GHSA-hp9c-qp4q-cpw3](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-hp9c-qp4q-cpw3). The same impact as above, via a tmux control mode layout with a zero-sized or oversized pane. This affects Ghostty 1.3.0 and 1.3.1.
- [GHSA-w9q4-5jvv-mcv4](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-w9q4-5jvv-mcv4). Clearing the screen into scrollback could corrupt memory if it deleted the scrollback page holding a styled or hyperlinked cursor. This only requires displaying malicious output, but only with a small `scrollback-limit` such as `0`. The default isn't known to be affected.
- [GHSA-2r63-vmw6-3m3c](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-2r63-vmw6-3m3c). A crafted directory name could make the zsh shell integration send arbitrary escape sequences, such as silently replacing the clipboard via OSC 52. bash was affected in a more limited way. This only requires `cd`-ing into a directory from untrusted content, such as a cloned repository.
- macOS: [GHSA-cw69-wm67-5pv8](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-cw69-wm67-5pv8). Cmd-clicking a crafted OSC 8 hyperlink could open unsafe local files or custom URL schemes, leading to arbitrary command execution. Ghostty now blocks unsafe targets and confirms custom URL schemes. This requires user interaction (cmd-click) to trigger.
- macOS: [GHSA-mfw9-xcr3-7gfp](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-mfw9-xcr3-7gfp). The same issue as above for links detected by the `link` configuration, including the default URL matcher. This requires user interaction (cmd-click) to trigger.
- macOS: [GHSA-v8cw-fg4j-jcc4](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-v8cw-fg4j-jcc4). Drag-and-drop text skipped paste protection, with the same impact as above. This requires user interaction (drag-and-drop) to trigger.
- macOS: [GHSA-mxqx-236q-wrv7](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-mxqx-236q-wrv7). Opening a file whose name contains control characters could run a different command than the one shown in the confirmation dialog. This requires a crafted file on your system and confirming the dialog.

Note: I requested CVEs for the above advisories weeks ago, but GitHub hasn't assigned them yet. If/when they're assigned, I will update the above with proper CVE numbers.

Ghostty 1.4 supports macOS 27 (Golden Gate). Most of the work was compatibility fixes:

- Tabs in the titlebar (`macos-titlebar-style = tabs`) lay out correctly again.
- The native tab bar no longer draws as a solid gray bar on top of your theme. It now lets the new glass style blend with your terminal background.
- `macos-titlebar-style = hidden` no longer covers the top lines of the terminal when Reduce Transparency is on.
- The app icon no longer has a thin border.
- The Shortcuts "New Window" action no longer opens two windows when Ghostty is running without any windows.

Ghostty 1.4 remains fully compatible with prior macOS versions back to and including macOS 13 (Ventura). See the [system requirements](https://ghostty.org/docs/install/release-notes/1-4-0#system-requirements) for more details.

> Ghostty 1.3.1 works on macOS 27, but it has some of the visual issues listed above, such as the gray tab bar.

Ghostty now supports Kitty graphics [animation](https://sw.kovidgoyal.net/kitty/graphics-protocol/#animation) and [relative placements](https://sw.kovidgoyal.net/kitty/graphics-protocol/#relative-placements). These were the last major features of the Kitty graphics protocol that Ghostty didn't support.

Programs that display animated images with the Kitty protocol, such as an animated GIF shown with `kitten icat`, now animate in Ghostty instead of showing a single still frame. Frame transmission, composition, and playback control are all supported, and animations pause while the terminal isn't visible. Relative placements let a program position one image relative to another image's placement, so the child image moves along with its parent.

We also did a full conformance pass against the specification and Kitty itself, fixing dozens of behavioral differences. For example, images now scroll with text inside scroll regions ([#4323](https://github.com/ghostty-org/ghostty/issues/4323) ), retransmitting an image ID replaces the old image ([#6711](https://github.com/ghostty-org/ghostty/issues/6711) ), and invalid image data now gets an error response instead of silence, which could leave clients hanging. The full list is in the [terminal capabilities](https://ghostty.org/docs/install/release-notes/1-4-0#terminal-capabilities) section.

Kitty graphics are faster, too. Image payloads are now parsed in bulk with SIMD instead of one byte at a time, making large image transfers **about 16x faster** to parse in our benchmarks (64 MiB of image data, x86\_64 Linux), and drawing images costs much less per frame.

Our Kitty graphics implementation now covers 100% of the published specification, making Ghostty (and libghostty) the first terminal to do this outside of Kitty itself.

Ghostty now transparently compresses scrollback that isn't visible, reducing the physical memory those pages use by **70% to 90%** for typical text-heavy history. Compression only runs while the terminal is idle and pages are decompressed on demand when you scroll back or search, so it has no measurable impact on I/O throughput.

Thanks to compression, **the default scrollback limit has been raised from 10 MB to 50 MB** per terminal. On platforms that support compression, a full scrollback still generally uses less physical memory than the old 10 MB limit did.

> Compression lowers *resident* (physical) memory, not *virtual* memory, so look at resident memory when measuring it. It is currently available on macOS and 64-bit Linux.

Beyond scrollback, memory usage is lower in many places:

- A new, empty terminal now uses about **16 KiB** of terminal page memory on macOS, down from 128 KiB in Ghostty 1.3.1.
- On macOS and Linux, memory freed by clearing or trimming scrollback is now returned to the OS instead of being held until the terminal closes.
- Hidden tabs release their GPU resources. On macOS, with one visible tab and 20 hidden tabs, GPU memory dropped from about 385 MiB to 18 MiB. Rebuilding them when a tab becomes visible again takes under a millisecond.

There are performance improvements across the board in Ghostty 1.4 that yield significant gains compared to prior Ghostty versions.

The biggest win came from a surprising discovery: on macOS, the kernel caps every read from a pty at about 1 KiB no matter how large the read buffer is. Previously, Ghostty processed each read as it arrived, so per-read overhead was paid every kilobyte, and the program writing output sat blocked while we parsed. Ghostty now drains the pty on one thread while parsing on another, raising end-to-end I/O throughput by **25% to 55%** on macOS (M4 Max, plain and Unicode text) over Ghostty 1.3.x.

VT processing itself is also much faster. In parser benchmarks, plain ASCII text went from 128 MB/s to 725 MB/s (5.7x), CJK text got 3.4x faster, and a 2.6 GB dataset of real-world terminal recordings from [asciinema](https://asciinema.org/) is processed about 25% faster. Together, these changes took `cat`-ing a 150 MB text file on macOS from 1.5 seconds to 566 milliseconds.

Other notable improvements:

- **Resize:** resizing a terminal with a large scrollback is about **6x faster** (120x80 with 10,000 lines of scrollback), and 3x to 5x faster with history full of CJK text or emoji.
- **Rendering:** the renderer holds the terminal lock **2.7x to 11x** less per frame, leaving more time for the I/O thread during heavy output.
- **Copy and search:** formatting terminal contents as plain text, HTML, or VT, which backs clipboard copy, `write_screen_file`, and scrollback search, is 1.5x to 8x faster.
- **Launch (macOS):** about 15% faster from launch to visible window, and 27% faster to the first rendered frame.
- **Idle energy:** on macOS, the renderer's display link now sleeps when there's nothing to draw. On GTK, hidden tabs stop rendering, matching macOS.
- **Large OSC sequences:** OSC 52 clipboard payloads parse about **30x faster**, and even short sequences like title changes are about 6x faster.

PRs: [#14052](https://github.com/ghostty-org/ghostty/issues/14052) [#14269](https://github.com/ghostty-org/ghostty/issues/14269)

The GTK app has a new rendering pipeline. It no longer uses `GtkGLArea`. Instead, the renderer draws with EGL on its own thread, exports each frame as a DMABUF, and hands it to GTK to display. Rendering is now triple-buffered, which should greatly reduce tearing, and no OpenGL calls run on the main thread anymore, which let us remove a number of workarounds.

The most visible result is crisp text under fractional scaling. Text and box-drawing characters are no longer blurry with fractional display scaling such as 125% or 150% ([#1938](https://github.com/ghostty-org/ghostty/issues/1938) ). We fixed this once before, but it came back after upstream GTK changes. Ghostty now renders at the window's true fractional scale, so every rendered pixel maps to exactly one pixel on screen.

The new render surface needs a system EGL library (see [Changes for Package Maintainers](https://ghostty.org/docs/install/release-notes/1-4-0#changes-for-package-maintainers)). On GPU drivers that can't export DMABUFs, Ghostty falls back to copying frames through the CPU, which is slower but works.

PRs: [#13962](https://github.com/ghostty-org/ghostty/issues/13962) [#13993](https://github.com/ghostty-org/ghostty/issues/13993) [#13995](https://github.com/ghostty-org/ghostty/issues/13995) [#13998](https://github.com/ghostty-org/ghostty/issues/13998) [#14002](https://github.com/ghostty-org/ghostty/issues/14002) [#14061](https://github.com/ghostty-org/ghostty/issues/14061)

Ghostty now implements the [Kitty clipboard protocol](https://sw.kovidgoyal.net/kitty/clipboard/) (OSC 5522) on both macOS and GTK. Ghostty 1.3 could parse the protocol but didn't implement it.

OSC 52 can only read and write plain text. The Kitty clipboard protocol lets programs running in the terminal read and write any kind of clipboard data, such as images or HTML, and lets them pick among the formats on the clipboard. Programs can also enable paste events (mode 5522), which tell the program what formats a paste contains so it can read the one it wants. This is how a terminal program can accept a pasted image, for example.

Clipboard access follows the existing `clipboard-read` and `clipboard-write` configurations. By default, reads prompt for permission and writes are allowed. The permission prompt shows a preview of the clipboard contents, including images. Programs that send a password can have your answer remembered for the rest of that terminal session. A new `clipboard-write-limit-bytes` configuration limits the size of a single write (default 64 MiB). A write over the limit fails and leaves the clipboard untouched.

PRs: [#10423](https://github.com/ghostty-org/ghostty/issues/10423) [#13706](https://github.com/ghostty-org/ghostty/issues/13706)

You can now rearrange splits on GTK by dragging them, matching the macOS feature introduced in Ghostty 1.3. When a tab has two or more splits, each split shows a drag handle at the top. Grab the handle and drop the split onto any other split, including splits in other tabs and windows. An overlay shows which side of the target split it will land on. The terminal contents, working directory, and running processes all move with it.

A new `drag-handle` configuration controls when drag handles are shown on both macOS and GTK: `auto` (default), `always`, or `never`. With `never`, splits can't be rearranged with the mouse. Hiding the handles was a common request from users who found them in the way.

On GTK, splits can only be dropped onto other splits. Dragging a split out to create a new tab or window is macOS-only.

PRs: [#14454](https://github.com/ghostty-org/ghostty/issues/14454) [#13494](https://github.com/ghostty-org/ghostty/issues/13494) [#14483](https://github.com/ghostty-org/ghostty/issues/14483) [#14538](https://github.com/ghostty-org/ghostty/issues/14538) [#14673](https://github.com/ghostty-org/ghostty/issues/14673) [#14375](https://github.com/ghostty-org/ghostty/issues/14375) [#14144](https://github.com/ghostty-org/ghostty/issues/14144)

Ghostty 1.4 includes dozens of improvements to core terminal emulation. We now run [esctest](https://github.com/ThomasDickey/esctest2), Thomas Dickey's terminal conformance suite, against Ghostty's terminal core in CI. Alongside that, we fixed many differences from xterm in cursor movement within margins, tab stops, character sets, mode reports, and more. You can find the full list of related changes in the [terminal capabilities](https://ghostty.org/docs/install/release-notes/1-4-0#terminal-capabilities) section.

Ghostty also supports several new sequences, including soft terminal reset (DECSTR), extended cursor position reports (DECXCPR), backarrow key mode (DECBKM), and screen size reports in characters (`CSI 19 t`). Programs can also now ask whether the terminal is visible using [visibility reports](https://rockorager.dev/misc/visibility-reports/) (mode 2033), so they can stop rendering while hidden.

Keyboard encoding also matches xterm more closely, with fixes for `modifyOtherKeys` mode 2 and legacy Alt-as-Escape encoding of non-ASCII keys.

Two new sequences are disabled by default because they can be abused by untrusted programs, including ones running on a remote machine:

```
# Allow programs to resize the window (CSI 8 t)
vt-window-resize-allowed = true

# Allow programs to request screen checksums (DECRQCRA)
vt-xt-checksum-report = true
```

PRs: [#12582](https://github.com/ghostty-org/ghostty/issues/12582) [#12814](https://github.com/ghostty-org/ghostty/issues/12814) [#13533](https://github.com/ghostty-org/ghostty/issues/13533) [#13844](https://github.com/ghostty-org/ghostty/issues/13844) [#14472](https://github.com/ghostty-org/ghostty/issues/14472) [#14854](https://github.com/ghostty-org/ghostty/issues/14854)

Ghostty 1.2 introduced [SSH shell integration features](https://ghostty.org/docs/features/ssh) as a work in progress. In Ghostty 1.4, they're backed by a new `ghostty +ssh` CLI action: a drop-in `ssh` wrapper that prepares the remote session for Ghostty and then runs the real `ssh` with your arguments forwarded unchanged.

```sh
ghostty +ssh user@example.com

# Or alias it so every ssh invocation goes through it
alias ssh='ghostty +ssh --'
```

Before connecting, `+ssh` installs Ghostty's terminfo on the remote host so the proper `xterm-ghostty` `TERM` value can be used, and forwards `COLORTERM`, `TERM_PROGRAM`, and `TERM_PROGRAM_VERSION`. If the terminfo install fails (for example, `tic` isn't available on the remote), it falls back to `TERM=xterm-256color`. Flags such as `--terminfo=false`, `--forward-env=false`, and `--verbose` control each step.

The `ssh-env` and `ssh-terminfo` shell integration features (still opt-in) now call `+ssh` too. Previously, each shell integration carried its own copy of this logic, which made up roughly a third of our shell integration scripts. Now bash, zsh, fish, elvish, and Nushell all behave identically, and you can get the same behavior from scripts or anywhere else by calling `ghostty +ssh` directly.

The terminfo install itself is also more reliable. Ghostty now always installs its own bundled terminfo rather than accepting whatever `xterm-ghostty` entry the remote already has, and it reinstalls automatically when a Ghostty update changes the terminfo. It also no longer needs `infocmp` or Ghostty's terminfo on the local machine. Installs are cached per host *and* port, so two machines behind one address no longer share a cache entry. And `ssh-env` no longer silently overrides `SetEnv` entries in your `~/.ssh/config` ([#11518](https://github.com/ghostty-org/ghostty/issues/11518) ).

The `+ssh-cache` command that manages this cache now takes positional destinations (`ghostty +ssh-cache user@example.com`) and has a new `--prune=30d` flag. See the [breaking changes](https://ghostty.org/docs/install/release-notes/1-4-0#breaking-changes) if you script against `+ssh-cache`.

**macOS:** The minimum required macOS version for Ghostty 1.4 remains unchanged (macOS 13 Ventura). Ghostty is now compatible with macOS 27.

**GTK:** Ghostty 1.4 requires **GTK 4.18** and **libadwaita 1.7**, up from GTK 4.14 and libadwaita 1.5 in Ghostty 1.3. This aligns with our [GTK/Adwaita version policy](https://ghostty.org/docs/linux/#supported-gtkadwaita-versions). Notably, Ubuntu 24.04 LTS doesn't meet this requirement. Systems with older GTK or Adwaita versions can work around this requirement by using an older version of Ghostty or the Flatpak package. [#14330](https://github.com/ghostty-org/ghostty/issues/14330)

**OpenGL (GTK):** The minimum required OpenGL version remains 4.3, but Ghostty now renders through EGL instead of GTK's OpenGL widget. This should be invisible for nearly everyone, but if Ghostty fails to start with an EGL error, please make sure your GPU driver provides a working EGL implementation.

> We previously announced that Ghostty 1.4 would require macOS 14. Nothing forced our hand to do this in this release, so we kept macOS 13 support. **We still plan to drop macOS 13 in a future release.** Apple dropped security support for macOS 13 in the fall of 2025, so we recommend upgrading regardless.

The following behaviors have changed in 1.4.0:

- `copy-on-select` has been reworked and now accepts `none`, `primary`, `clipboard`, or `both`. **The meaning of `clipboard` has changed:** it previously copied to both the selection clipboard and the system clipboard, and now copies only to the system clipboard. If you set `copy-on-select = clipboard` and want the old behavior, change it to `both`. [#12600](https://github.com/ghostty-org/ghostty/issues/12600) [#12604](https://github.com/ghostty-org/ghostty/issues/12604)
- macOS: `copy-on-select` now defaults to `none` (previously `true`), so selecting text no longer copies it anywhere and middle-click paste of the selection no longer works by default. To restore the 1.3 behavior, set `copy-on-select = primary`. Note that an explicit `copy-on-select = true` on macOS now copies selections to the system clipboard, which is different from 1.3. [#12600](https://github.com/ghostty-org/ghostty/issues/12600) [#12604](https://github.com/ghostty-org/ghostty/issues/12604)
- macOS: `cmd+arrow_up` and `cmd+arrow_down` now run `jump_to_prompt` again, matching Terminal.app and Ghostty 1.2. In 1.3, these keys were hardcoded to scroll to the top and bottom and couldn't be rebound. To keep the 1.3 behavior, set `keybind = cmd+arrow_up=scroll_to_top` and `keybind = cmd+arrow_down=scroll_to_bottom`. [#12245](https://github.com/ghostty-org/ghostty/issues/12245)
- GTK: The default `ctrl+shift+page_up` and `ctrl+shift+page_down` keybinds now move the current tab left and right (`move_tab`), matching Firefox, GNOME Terminal, and VS Code. `jump_to_prompt` moved to `ctrl+shift+arrow_up` and `ctrl+shift+arrow_down`, so programs running in the terminal no longer receive those keys. If a program you use needs them, unbind them with `keybind = ctrl+shift+arrow_up=unbind` and `keybind = ctrl+shift+arrow_down=unbind`. [#4998](https://github.com/ghostty-org/ghostty/issues/4998) [#12458](https://github.com/ghostty-org/ghostty/issues/12458)

The list below contains deprecations that remain compatible today through a compatibility layer, but may break in a future release if they are ignored:

- `scrollback-limit` has been renamed to `scrollback-limit-bytes`, to make room for the new `scrollback-limit-lines`. [#13473](https://github.com/ghostty-org/ghostty/issues/13473)
- `copy-on-select = true` is replaced with `copy-on-select = primary` on Linux and FreeBSD, or `copy-on-select = clipboard` on macOS. `copy-on-select = false` is replaced with `copy-on-select = none`. [#12600](https://github.com/ghostty-org/ghostty/issues/12600) [#12604](https://github.com/ghostty-org/ghostty/issues/12604)

There is no set timeline to remove these deprecations, but we recommend adapting to the new configurations sooner rather than later to avoid any possible disruptions in the future.

- Scrollback history is now transparently compressed while the terminal is idle, reducing the physical memory used by compressed scrollback by 70% to 90% for typical text. Compression is available on macOS and 64-bit Linux and can be disabled with the new `scrollback-compression` configuration. Because of this, the default scrollback limit has been raised from 10 MB to 50 MB, which on average still uses less memory than a full scrollback did previously. [#13264](https://github.com/ghostty-org/ghostty/issues/13264)
- A new configuration `scrollback-limit-lines` limits scrollback by number of lines instead of bytes. The existing `scrollback-limit` configuration has been renamed to `scrollback-limit-bytes` (the old name continues to work). If both are set, the first limit reached applies, and both accept `unlimited`. [#13473](https://github.com/ghostty-org/ghostty/issues/13473)
- `copy-on-select` now accepts `none`, `primary`, `clipboard`, and `both` and no longer affects middle-click paste (see `middle-click-action`). `clipboard` now copies only to the system clipboard, so use `both` for the previous behavior. The default on macOS is now `none`. See the [breaking changes](https://ghostty.org/docs/install/release-notes/1-4-0#breaking-changes) for migration details. [#12600](https://github.com/ghostty-org/ghostty/issues/12600)
- A new configuration `middle-click-action` configures the behavior of middle-clicking: `primary-paste` (default) pastes from the selection clipboard, `clipboard-paste` pastes from the system clipboard, and `ignore` does nothing. [#12478](https://github.com/ghostty-org/ghostty/issues/12478)
- A new binding action `move_tab_to_new_window` moves the current tab into a new window of its own. It is also available in the command palette. [#2630](https://github.com/ghostty-org/ghostty/issues/2630)
- A new CLI command `+explain-config` prints the documentation for a configuration option or binding action, e.g. `ghostty +explain-config font-size`. [#11546](https://github.com/ghostty-org/ghostty/issues/11546)
- The `+explain-config` and `+show-config` CLI commands now page their output through `$GHOSTTY_PAGER` or `$PAGER` (falling back to `less`) when run interactively. Paging can be disabled with `--no-pager` or by setting the pager to an empty value. [#11940](https://github.com/ghostty-org/ghostty/issues/11940)

As with 1.3, libghostty isn't directly part of the Ghostty 1.4 release. But a large part of the 1.4 development cycle went into libghostty, so here's an update.

Over the past 6 months, the C API for libghostty-vt has grown from a parser and a few encoders into a complete terminal emulator API, adopted by dozens of free and commercial terminal emulators used by millions of people. It's hard to quantify exactly, but the number of people using a libghostty-based terminal is confidently several times the number of people using the Ghostty GUI.

libghostty-vt now builds for macOS, Linux, Windows (MSVC and GNU), FreeBSD, Android, iOS, and WebAssembly, and CI continuously verifies every one of these targets. The goal is for libghostty-vt to be generally usable everywhere, within reason, so if you want more target support, let us know!

It's also easier to integrate libghostty-vt into existing build systems. There's CMake support, Nix packaging, an xcframework, and a source tarball, in addition to the existing pkg-config file. **libghostty-vt no longer needs libc++, and it can build freestanding.**

The API is still marked as a work in progress and broke compatibility several times during this cycle, so expect more breaking changes before a tagged release. The [API documentation](https://libghostty.tip.ghostty.org/index.html) and the [Zig, C, C++, Swift, and WebAssembly examples](https://github.com/ghostty-org/ghostty/tree/main/example) (now over 30) are kept up to date with `main`.

We're going to do a final pass over the C API, break ABI one more time, and then likely tag a libghostty 1.0 release very soon.

In this cycle, he led the upgrade to Zig 0.16, moved the build off Zig's deprecated `@cImport`, updated the bundled Fontconfig, and more. He's also the author of [z2d](https://github.com/vancluever/z2d), the 2D graphics library Ghostty uses to draw box-drawing characters and other sprite glyphs.

If you'd like to support Ghostty, please visit our [sponsorship page](https://ghostty.org/docs/sponsor).

The primary focus of the roadmap continues to be libghostty functionality, stability, and portability. During the last release cycle, I said I aimed to tag a libghostty release. We haven't done that yet, but I'm confident we will do so before Ghostty 1.5.

libghostty is a project that continues to be the tide that lifts all boats. libghostty improvements tie directly to Ghostty GUI improvements as well as dozens of other large projects in the ecosystem. As more large projects adopt libghostty, libghostty tends to get more testing and attention, and this creates a cycle that yields the most gain for terminal emulators everywhere.

macOS and GTK builds of Ghostty have talented, capable maintainer teams that are continuing to improve them, so they're not neglected by any means! As a project, we've decided to drop any roadmap for Windows support in the Ghostty GUI. libghostty fully supports Windows (and we test it in CI), and the official stance now is that downstream projects should use that.

Our release cycle remains 6 months. This release was delayed by one month, but Ghostty 1.5 is planned for March 2027. libghostty will have a separate release cycle.
