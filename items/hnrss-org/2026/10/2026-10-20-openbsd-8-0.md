### What's New

This is a partial list of new features and systems included in OpenBSD 8.0. For a comprehensive list, see the [changelog](https://www.openbsd.org/plus80.html) leading to 8.0.

- Platforms specific improvements:
  - [amd64](https://www.openbsd.org/amd64.html):
    - Raised the size of amd64 kernel virtual address space from 4G to 512G.
    - [pmap(9)](https://man.openbsd.org/pmap.9) direct map now placed at a random location.
    - Sped up swap encryption by using AES cpu instructions.
  - [arm64](https://www.openbsd.org/arm64.html):
    - Added hibernate support.
    - Sped up swap encryption by using AES cpu instructions.
    - Implemented bounce buffers.
  - [luna88k](https://www.openbsd.org/luna88k.html):
    - Fixed m88k multiple CMMU register writes.
    - Extended m88k kernel-mode CMMU fault handling to handle write protection faults.
    - Ensure luna88k m8820x\_initialize\_cpu() initializes logical CPU #0 on non-MP kernels.
    - Faster CMMU walk in luna88k m8820x\_cpu\_number().
  - [riscv64](https://www.openbsd.org/riscv64.html):
    - Detect CPU extensions and advertise those usable by userland through elf\_aux\_info(3) AT\_HWCAP and AT\_HWCAP2 queries.
    - Added kernel support for the 'V' vector extension.
    - Implemented bounce buffers.
    - Added support for RISC-V Advanced Interrupt Architecture; added [imsic(4)](https://man.openbsd.org/imsic.4) and [aplic(4)](https://man.openbsd.org/aplic.4) drivers.
    - Added kernel support for the Sstc timer extension.
  - [sparc64](https://www.openbsd.org/sparc64.html):
    - Added bounds check for the sparc64 relocation flags table.
    - Switched sparc64 to LLVM toolchain.
    - Improved memory alignment on SPARCV9.
  - Other [architectures](https://www.openbsd.org/plat.html):
    - Retired support for loongson architecture (not working with Clang 22).
    - Various RISC-V and MIPS bugfixes for LLVM.
    - Fixed encoding of hppa protection bits.
  - More platform specific changes can be found in the [hardware support](https://www.openbsd.org/80.html#hardware_support) section below.
- Various kernel improvements:
  - Fixed memory size calculation in [open\_wmemstream(3)](https://man.openbsd.org/open_wmemstream.3).
  - Fixed [semop(2)](https://man.openbsd.org/semop.2) semaphore id being destroyed/replaced during context switch.
  - Improved inactive page queue heuristics for pagedaemon swapping pages/freeing memory.
  - Added [getexecpath(3)](https://man.openbsd.org/getexecpath.3) to provide copy of the [elf(5)](https://man.openbsd.org/elf.5) program's execution path.
  - More preparations for larger disklabel.
- Suspend/Hibernate Support:
  - Enabled suspend/resume for [qwz(4)](https://man.openbsd.org/qwz.4).
  - Made [ufshci(4)](https://man.openbsd.org/ufshci.4) survive a suspend on the Samsung Galaxy Book4 Edge and HONOR MagicBook Art 14 Snapdragon.
  - Stopped waking a suspended laptop when lid is closed and machdep.lidaction=0.
  - Added a global sleep mode variable to distinguish hibernate from 'normal' suspend.
  - Added suspend/resume support for [qcuart(4)](https://man.openbsd.org/qcuart.4).
  - Added support for wakeup interrupts to [bytgpio(4)](https://man.openbsd.org/bytgpio.4), fixes IdeaPad resuming from suspend.
  - Validate size of chunks copied to piglet during hibernate unpacking of disk image.
  - Validate on-disk image sizes against integer overflow when reading chunks in unhibernate.
  - Prevent disk image overreads when reading the chunktable in unhibernate.
  - Clean up the framebuffer after unhibernate.
  - Made failure to allocate a dedicated queue for [nvme(4)](https://man.openbsd.org/nvme.4) hibernate support non-fatal.
- Direct Rendering Manager and graphics drivers:
  - Updated [drm(4)](https://man.openbsd.org/drm.4) to Linux 6.18.53.
  - Support for Intel Arc A-Series (DG2/Alchemist) graphics cards in [inteldrm(4)](https://man.openbsd.org/inteldrm.4).
  - Increased kernel virtual address space on amd64 allows mapping more than 4GB of VRAM.
  - Workaround [inteldrm(4)](https://man.openbsd.org/inteldrm.4) GuC timeout errors seen on some Alder Lake systems.
- VMM/VMD improvements:
  - Added MP support for up to 64 VCPUs per guest VM.
  - Redesigned to use files to manage VM ownership.
  - Added x2apic mode support for guest virtual machines.
  - Fix for when [vmd(8)](https://man.openbsd.org/vmd.8) does not detect kernel on startup.
  - Provide faulting GPA to [vmd(8)](https://man.openbsd.org/vmd.8) for MMIO exits from [vmm(4)](https://man.openbsd.org/vmm.4).
  - Refactored [vmm(4)](https://man.openbsd.org/vmm.4) exit handling and correct RIP adjustment.
  - Added support for variable length instructions in VMX paths to [vmm(4)](https://man.openbsd.org/vmm.4).
  - Prevent OOB reads by [vmd(8)](https://man.openbsd.org/vmd.8) in 32 and 64-bit [elf(5)](https://man.openbsd.org/elf.5) loaders with malformed [elf(5)](https://man.openbsd.org/elf.5) files.
  - Implemented missing lapic/ioapic modes to fix [vmd(8)](https://man.openbsd.org/vmd.8) support for 32-bit linux guests.
  - Added checksum offload for [vmd(8)](https://man.openbsd.org/vmd.8) guests.
  - MSI/MSI-X virtio device interrupt support added.
  - Support actually split split-virtqueues in [vmd(8)](https://man.openbsd.org/vmd.8).
  - Added i82093aa ioapic and i82489dx-compatible lapic emulation to [vmd(8)](https://man.openbsd.org/vmd.8).
  - Improved qcow handling.
- Various new userland features:
  - [netstat(1)](https://man.openbsd.org/netstat.1) can now print interface multicast counter; made '-q' more specific.
  - Adjusted [ddb(4)](https://man.openbsd.org/ddb.4) default 'ps' output, print 'struct process' and 'struct proc' separately.
  - Made [mount(8)](https://man.openbsd.org/mount.8) support DUIDs with -u; preserve DUID when updating file system.
  - Implemented control of midithru ports with [sndioctl(1)](https://man.openbsd.org/sndioctl.1).
  - Allow list elements to be added or removed by [sndioctl(1)](https://man.openbsd.org/sndioctl.1).
  - Added the [sndiod(8)](https://man.openbsd.org/sndiod.8) server.mode control making the setting dynamic, changeable via [sndioctl(1)](https://man.openbsd.org/sndioctl.1).
- More bugfixes and tweaks in userland:
  - Ensure [elf(5)](https://man.openbsd.org/elf.5) header and program header fit into the shared library when loading.
  - Fixed leak of key memory in [getpwent(3)](https://man.openbsd.org/getpwent.3) yp\_next().
  - In [patch(1)](https://man.openbsd.org/patch.1), solved an infinite loop on malformed [ed(1)](https://man.openbsd.org/ed.1) script input.
  - Use [execv(3)](https://man.openbsd.org/execv.3) absolute-path in [authpf(8)](https://man.openbsd.org/authpf.8), [pflogd(8)](https://man.openbsd.org/pflogd.8), [ldapd(8)](https://man.openbsd.org/ldapd.8), [ldpd(8)](https://man.openbsd.org/ldpd.8), [lpd(8)](https://man.openbsd.org/lpd.8), [radiusd(8)](https://man.openbsd.org/radiusd.8), [snmpd(8)](https://man.openbsd.org/snmpd.8).
  - [uaudio(4)](https://man.openbsd.org/uaudio.4) now tests the reported format and channels are usable.
  - Stopped [sndiod(8)](https://man.openbsd.org/sndiod.8) aborting if a MIDI endpoint connects with non-empty buffers.
  - Fixed two missing checks of file\_new() return value in [sndiod(8)](https://man.openbsd.org/sndiod.8).
  - Fixed [npppd(8)](https://man.openbsd.org/npppd.8) LCP MRU option handing.
  - Adjust [pstat(8)](https://man.openbsd.org/pstat.8) to return the pid of the session leader process; allow '-t -M' to work.
  - Made [eigrpd(8)](https://man.openbsd.org/eigrpd.8) validate the prefixlen to avoid overflow.
  - Made [sndiod(8)](https://man.openbsd.org/sndiod.8) allocate all midithru structures on the heap.
- Improved hardware support and driver bugfixes, including:
  - Enabled the GXTP7936 touchscreen on the Samsung Galaxy Book4 Edge.
  - Added support for the riscv64 K3 PCIe/USB3 combo PHY.
  - Enabled [gpioleds(4)](https://man.openbsd.org/gpioleds.4) on riscv64.
  - In [smte(4)](https://man.openbsd.org/smte.4) (SpacemiT K1 Ethernet device), improved error checking of received packets.
  - Fixed regular MSI interrupts on the SpacemiT K1 SoC.
  - Added support for the SpacemiT K3 SoC to [smtclock(4)](https://man.openbsd.org/smtclock.4).
  - Added SC7280 support to [qcgpio(4)](https://man.openbsd.org/qcgpio.4).
  - Added support for the SpacemiT K3 [dwpcie(4)](https://man.openbsd.org/dwpcie.4) PCIe controller.
  - Added RK3528 I2C5 clock, used in the Radxa E24C.
  - Added ACPI hardware IDS for Qualcomm Glymur (X2) SoC.
  - Implemented page table mirroring in [apldart(4)](https://man.openbsd.org/apldart.4); enable IOMMU for Apple USB controllers.
  - New [samsabi(4)](https://man.openbsd.org/samsabi.4) driver for the Samsung Advanced BIOS Interface (SABI).
  - New [sambat(4)](https://man.openbsd.org/sambat.4) driver for Samsung laptop battery monitor.
  - New [rkotp(4)](https://man.openbsd.org/rkotp.4) driver for Rockchip OTP memory.
  - Added support for the RK8600 regulator used for CPU voltage on Radxa Zero 3 boards.
  - Added more AMD "Krackan Point" device ids.
  - Fixed HONOR MagicBook Touchpad multitouch support.
  - Fixed [esp(4)](https://man.openbsd.org/esp.4) FIFO memory overflow.
  - Fixed potential memory leak in [softraid(4)](https://man.openbsd.org/softraid.4) rebuild.
  - Fixed [softraid(4)](https://man.openbsd.org/softraid.4) rebuild on disks with 4096-byte sectors.
  - Fixed high memory mbufs for 64-bit DMA capable [re(4)](https://man.openbsd.org/re.4).
- New or improved network hardware support:
  - Added support for Panther Lake and Wildcat Lake Ethernet devices to [em(4)](https://man.openbsd.org/em.4).
  - Added support for Intel E610 Ethernet devices to the [ix(4)](https://man.openbsd.org/ix.4) driver.
- Added or improved wireless network drivers:
  - Properly handle potential case of empty packets returned from [qwx(4)](https://man.openbsd.org/qwx.4) hardware.
  - Added missing DMA syncs for [qwx(4)](https://man.openbsd.org/qwx.4) SRNG DMA descriptor memory.
  - Properly handle [qwx(4)](https://man.openbsd.org/qwx.4) VIF DMA map allocation failures at attach time.
  - Fixed use of stale pointers on the [qwx(4)](https://man.openbsd.org/qwx.4) vif list which caused crashes.

  - Avoid race condition in [qwx(4)](https://man.openbsd.org/qwx.4) device during power-on.
  - Use the ioctl rwlock correctly in [qwx(4)](https://man.openbsd.org/qwx.4) qwx\_activate().
  - Ensure [qwx(4)](https://man.openbsd.org/qwx.4) rx\_ring->bufs\_max and freemap are always initialised correctly.
  - Stopped [qwx(4)](https://man.openbsd.org/qwx.4) init task waiting for the ioctl lock to become available.
  - Made [qwx(4)](https://man.openbsd.org/qwx.4) properly errors which occur in qwx\_qmi\_fw\_init\_done().
  - Fixed roaming between APs with [qwx(4)](https://man.openbsd.org/qwx.4).
  - Always allow data frame interrupts in [qwx(4)](https://man.openbsd.org/qwx.4) while the interface is UP.
  - Added support for 40MHz channels to [qwx(4)](https://man.openbsd.org/qwx.4).
  - Made [qwx(4)](https://man.openbsd.org/qwx.4) only allocate a new mbuf when a free Rx ring slot is available.
  - Avoid calling bus\_dmamap\_create() from interrupt context in [qwx(4)](https://man.openbsd.org/qwx.4).
  - Handle country code events sent by [qwx(4)](https://man.openbsd.org/qwx.4) firmware to make association more reliable.
  - Reset [qwx(4)](https://man.openbsd.org/qwx.4) command ring 'queued' counter when the command ring gets reset.
  - Ensure that [qwx(4)](https://man.openbsd.org/qwx.4) nq flags are always cleared when switching net80211 state.
  - Fixed number of tx/rx streams set in [qwx(4)](https://man.openbsd.org/qwx.4) mac config.
  - Made [qwx(4)](https://man.openbsd.org/qwx.4) send the PMF good-bye deauth frame when hopping out of RUN state.
  - Ensure no new tasks get scheduled while IFF\_RUNNING is in qwx\_stop(). Prevents [qwz(4)](https://man.openbsd.org/qwz.4) crash.
  - Make [qwx(4)](https://man.openbsd.org/qwx.4) prefer ic\_bss over the ephemeral node in the scan tree.
  - Add peer to [qwx(4)](https://man.openbsd.org/qwx.4) firmware after starting the vdev, not before. Fixes a firmware crash.
  - Add 802.11n support to [qwx(4)](https://man.openbsd.org/qwx.4). Advertise HT capabilities and pass HT/QoS peer association.
  - Ask [qwx(4)](https://man.openbsd.org/qwx.4) firmware to move into M3 state before resetting the device.
  - Avoid calling bus\_dmamap\_destroy() from interrupt context in [qwx(4)](https://man.openbsd.org/qwx.4).
  - Added 802.11n with 40MHz width to [qwz(4)](https://man.openbsd.org/qwz.4).
  - Let [qwz(4)](https://man.openbsd.org/qwz.4) handle QoS in native WiFi frames.
- Installer, upgrade, bootloader, and pkg-tools improvements:
  - Harmonise [installurl(5)](https://man.openbsd.org/installurl.5) handling in [pkg\_add(1)](https://man.openbsd.org/pkg_add.1), [sysupgrade(8)](https://man.openbsd.org/sysupgrade.8), and [syspatch(8)](https://man.openbsd.org/syspatch.8).
  - Fixed free space check by [fw\_update(8)](https://man.openbsd.org/fw_update.8) for unqualified filenames.
  - Set limit on the size of files [fw\_update(8)](https://man.openbsd.org/fw_update.8) can download.
  - Stricter validation in [fw\_update(8)](https://man.openbsd.org/fw_update.8) to no longer treat untrusted comments as data.
  - [pkg\_add(1)](https://man.openbsd.org/pkg_add.1) now detects and overcomes some endless loops with merge-sets.
  - Clean trailing slashes from [fw\_update(8)](https://man.openbsd.org/fw_update.8) FWURL.
  - Removed current directory from default [pkg\_add(1)](https://man.openbsd.org/pkg_add.1) search path.
  - Improved downloading of firmware by filename in [fw\_update(8)](https://man.openbsd.org/fw_update.8).
  - Improved [fw\_update(8)](https://man.openbsd.org/fw_update.8) error when SHA256.sig is not found.
  - [fw\_update(8)](https://man.openbsd.org/fw_update.8) now checks signature of local SHA256.sig.
  - In [fw\_update(8)](https://man.openbsd.org/fw_update.8), made [tar(1)](https://man.openbsd.org/tar.1) skip files outside expected locations.
  - Stopped [syspatch(8)](https://man.openbsd.org/syspatch.8) downloading entire tgz file when looking for a potential update.

Quick installer information for people familiar with OpenBSD, and the use of the "[disklabel](https://man.openbsd.org/disklabel.8) -E" command. If you are at all confused when installing OpenBSD, read the relevant INSTALL.\* file as listed above!

### OpenBSD/alpha:

If your machine can boot from CD, you can write *install80.iso* or *cd80.iso* to a CD and boot from it. Refer to INSTALL.alpha for more details.

### OpenBSD/amd64:

If your machine can boot from CD, you can write *install80.iso* or *cd80.iso* to a CD and boot from it. You may need to adjust your BIOS options first.

If your machine can boot from USB, you can write *install80.img* or *miniroot80.img* to a USB stick and boot from it.

If you can't boot from a CD, floppy disk, or USB, you can install across the network using PXE as described in the included INSTALL.amd64 document.

If you are planning to dual boot OpenBSD with another OS, you will need to read INSTALL.amd64.

### OpenBSD/arm64:

Depending on your hardware, you can write *install80.iso* or *cd80.iso* to a CD and boot from it, or write a system specific miniroot to an SD card and boot from it after connecting to the serial console. Refer to INSTALL.armv64 for more details.

### OpenBSD/armv7:

Write a system specific miniroot to an SD card and boot from it after connecting to the serial console. Refer to INSTALL.armv7 for more details.

### OpenBSD/hppa:

Boot over the network by following the instructions in INSTALL.hppa or the [hppa platform page](https://www.openbsd.org/hppa.html#install).

### OpenBSD/i386:

If your machine can boot from CD, you can write *install80.iso* or *cd80.iso* to a CD and boot from it. You may need to adjust your BIOS options first.

If your machine can boot from USB, you can write *install80.img* or *miniroot80.img* to a USB stick and boot from it.

If you can't boot from a CD, floppy disk, or USB, you can install across the network using PXE as described in the included INSTALL.i386 document.

If you are planning on dual booting OpenBSD with another OS, you will need to read INSTALL.i386.

### OpenBSD/landisk:

Write *miniroot80.img* to the start of the CF or disk, and boot normally.

### OpenBSD/luna88k:

Copy 'boot' and 'bsd.rd' to a Mach or UniOS partition, and boot the bootloader from the PROM, and then bsd.rd from the bootloader. Refer to the instructions in INSTALL.luna88k for more details.

### OpenBSD/macppc:

Burn the *install80.iso* image from a mirror site to a CDROM, and power on your machine while holding down the *C* key until the display turns on and shows *OpenBSD/macppc boot*.

Alternatively, at the Open Firmware prompt, enter *boot cd:,ofwboot /8.0/macppc/bsd.rd*

### OpenBSD/octeon:

After connecting a serial port, boot bsd.rd over the network via DHCP/tftp. Refer to the instructions in INSTALL.octeon for more details.

### OpenBSD/powerpc64:

To install, write *install80.img* or *miniroot80.img* to a USB stick, plug it into the machine and choose the *OpenBSD install* menu item in Petitboot. Refer to the instructions in INSTALL.powerpc64 for more details.

### OpenBSD/riscv64:

To install, write *install80.img* or *miniroot80.img* to a USB stick, and boot with that drive plugged in. Make sure you also have the microSD card plugged in that shipped with the HiFive Unmatched board. Refer to the instructions in INSTALL.riscv64 for more details.

### OpenBSD/sparc64:

Burn the image from a mirror site to a CDROM, boot from it, and type *boot cdrom*.

If this doesn't work, or if you don't have a CDROM drive, you can write *floppy80.img* or *floppyB80.img* (depending on your machine) to a floppy and boot it with *boot floppy*. Refer to INSTALL.sparc64 for details.

Make sure you use a properly formatted floppy with NO BAD BLOCKS or your install will most likely fail.

You can also write *miniroot80.img* to the swap partition on the disk and boot with *boot disk:b*.

If nothing works, you can boot over the network as described in INSTALL.sparc64.

### Notes about the source code

`src.tar.gz` contains a source archive starting at `/usr/src`. This file contains everything you need except for the kernel sources, which are in a separate archive. To extract:

> ```
> # mkdir -p /usr/src
> # cd /usr/src
> # tar xvfz /tmp/src.tar.gz
> ```

`sys.tar.gz` contains a source archive starting at `/usr/src/sys`. This file contains all the kernel sources you need to rebuild kernels. To extract:

> ```
> # mkdir -p /usr/src/sys
> # cd /usr/src
> # tar xvfz /tmp/sys.tar.gz
> ```

Both of these trees are a regular CVS checkout. Using these trees it is possible to get a head-start on using the anoncvs servers as described [here](https://www.openbsd.org/anoncvs.html). Using these files results in a much faster initial CVS update than you could expect from a fresh checkout of the full OpenBSD source tree.

### Ports Tree

A ports tree archive is also provided. To extract:

> ```
> # cd /usr
> # tar xvfz /tmp/ports.tar.gz
> ```

Go read the [ports](https://www.openbsd.org/faq/ports/index.html) page if you know nothing about ports at this point. This text is not a manual of how to use ports. Rather, it is a set of notes meant to kickstart the user on the OpenBSD ports system.

The *ports/* directory represents a CVS checkout of our ports. As with our complete source tree, our ports tree is available via [AnonCVS](https://www.openbsd.org/anoncvs.html). So, in order to keep up to date with the -stable branch, you must make the *ports/* tree available on a read-write medium and update the tree with a command like:

> ```
> # cd /usr/ports
> # cvs -d anoncvs@server.openbsd.org:/cvs update -Pd -rOPENBSD_8_0
> ```

\[Of course, you must replace the server name here with a nearby anoncvs server.\]

Note that most ports are available as packages on our mirrors. Updated ports for the 8.0 release will be made available if problems arise.

If you're interested in seeing a port added, would like to help out, or just would like to know more, the mailing list [ports@openbsd.org](https://www.openbsd.org/mail.html) is a good place to know.
